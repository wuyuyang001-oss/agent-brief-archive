ICAE-Bench: Evaluating Coding Agents as Interactive Project Builders

作者：Zhongyuan Peng, Dan Huang, Chuyu Zhang, Caijun Xu, Changyi Xiao, Shibo Hong, David Lo, Lin Qiu, Xuezhi Cao, Jiyuan He, Yixin Cao
发布日期：2026-07-23
链接：arXiv · 官方 HTML · 代码 / 项目页

此前遇到的问题主流 coding benchmark 给出完整规格，无法评估 Agent 是否能把模糊产品意图澄清、实现并在长程集成中守住隐藏约束。
研究做法从可执行开源仓库反向构造 480 个、12 种语言的模糊需求；自动 User Agent 只能依据 Grounded User Agent Data 回答；用黑盒测试和语义、API、结构、设计、交互指标联合诊断。
关键结论完整集上 Claude Opus 4.8 Overall 38.2%、GPT-5.5 37.2%；Agent 常复现可见行为，却在隐藏约束、边界条件和长期集成上失败。交互预算从 8 增至 16，Overall 22.9%→37.4%，增至 24 反降至 34.4%。
与既有工作的差异把“需求澄清质量”与“最终仓库质量”放入同一可执行评测，而不是把用户模拟器当无限制的答案机。
可信度中。480 tasks、12 languages、代码与数据公开，指标较完整；但用户模拟与测试构造共享来源，尚无真实 PM/用户对话的独立复现。
局限自动用户并不等同真实产品协商；更大交互预算会引入冗余，因果机制尚未分离；黑盒和 critic 指标仍可能偏向黄金仓库的实现形态。
后续进展 / 待验证产品评测应同时记录 clarification coverage、无依据承诺、集成回归和每次澄清的边际收益，而不是只看最终 pass rate。
展开英文简介与逐段中文翻译

English overview

ICAE-Bench evaluates coding agents as interactive project builders rather than static patch generators. Its 480 tasks span 12 languages and begin with fuzzy product requirements derived from executable open-source repositories. A grounded User Agent reveals hidden constraints without inventing requirements, while black-box tests and multidimensional diagnostics measure functional, semantic, structural, design, and interaction quality. Results show that visible behavior is easier to reproduce than hidden constraints and long-horizon integration, and that asking more questions is not monotonically beneficial.

对应中文翻译

ICAE-Bench 将 Coding Agent 评估为交互式项目构建者，而非静态补丁生成器。480 个任务覆盖 12 种语言，从可执行开源仓库派生的模糊产品需求开始；受约束的 User Agent 只揭示已有隐藏条件，不创造新需求。黑盒测试与功能、语义、结构、设计和交互诊断共同评分。实验显示，可见行为比隐藏约束和长程集成更容易复现，而且提问更多并不单调带来更好结果。
