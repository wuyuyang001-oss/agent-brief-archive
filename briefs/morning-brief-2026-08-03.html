此前遇到的问题生产 Agent 对重复 SOP 节点每次重新解释说明、发现后端 schema 并生成 MCP 查询代码；一个节点需 10–20 轮，复杂告警超过 100 轮，延迟和随机错误被反复支付。
研究做法离线由数据采集 Agent 在真实环境取得 trace、schema 和值，tool-maker 生成候选，reflector 依据标签测试修复；上线后每节点调用确定性版本化工具，缺失或失败时回退 CodeAct。
关键结论在 44 决策节点 / 19 行动节点 SOP 中，工具调用使生产 p50 延迟下降 42%；1,500 个历史告警上 Qwen3 32B 准确率 97.2%→98.2%，GLM-4.5-Air 98.3%→99.2%，相对错误率最多下降 53%；直接调用架构受控消融进一步降低 p50 62%。
与既有工作的差异不是让 Agent 在运行时不断发明工具，而是将重复步骤在构建期编译、测试和版本化，把灵活性留给 fallback，把稳定路径变成可审计软件资产。
可信度中等：8,011 训练和 8,022 评估节点案例、时间切分、3 seeds、bootstrap-by-task 5,000 次、超过 5,000 次生产调用；但作者也是部署方，无公开代码/数据或独立复现。
局限单一物流告警域、后端稳定且 SOP 结构化；线上比较部分混入模型与架构差异，虽另有受控消融；绝对准确率仅约提升 1 个百分点；规范缺失仍是上限，无法外推到开放式任务。
后续进展 / 待验证验证跨域迁移、schema 漂移恢复、恶意或错误 trace、防止 repair unlearn 正确代码，以及工具 registry 的审批、回滚和权限隔离。

English overview

Production LLM agents often regenerate code for the same procedural step, repeatedly paying the cost of schema discovery, tool selection, and multi-turn correction. This work moves that effort to build time. A data-collector agent executes against live MCP backends, a tool-maker synthesizes a candidate from the resulting trace, and a reflector-driven repair loop validates it against labeled cases. At runtime, versioned tools return structured true, false, or no-data verdicts, while CodeAct remains available as a fallback.

In a fulfillment-center alarm-triage deployment, the method covers a 44-node SOP and more than 5,000 production tool invocations. It reduces production p50 latency by 42%, lowers output tokens and turns, and reduces end-to-end error rate by up to 53% relative on 1,500 historical alarms. A controlled direct-call ablation cuts p50 latency by another 62%. The evidence is operationally valuable but domain-specific: the backend is comparatively stable, the SOP is structured, code and data are not public, and there is no independent reproduction.

对应中文翻译

生产 LLM Agent 经常为同一流程步骤重新生成代码，反复支付 schema 发现、工具选择和多轮纠错成本。这项工作把这些成本移到构建期：数据采集 Agent 在真实 MCP 后端执行，tool-maker 根据 trace 合成候选工具，再由 reflector 驱动的修复循环用标签案例验证。运行时，版本化工具返回 true、false 或 no-data 的结构化判断，同时保留 CodeAct 作为回退。

在履约中心告警分诊部署中，该方法覆盖 44 节点 SOP 和超过 5,000 次生产工具调用。它把生产 p50 延迟降低 42%，减少输出 token 与轮次，并在 1,500 个历史告警上将端到端错误率相对降低最多 53%。受控的直接调用消融又降低 p50 62%。这些证据具有运营价值，但局限于具体领域：后端相对稳定、SOP 结构化、代码与数据未公开，且没有独立复现。
