移动 Agent 的 Judge 需要先被评测

新论文 / 证据增强
核心结论
MobileJudgeBench 发现，抽取轨迹截图的简单 Judge 基线可匹敌或超过复杂专用方法；Judge 的底层模型往往比流水线复杂度更重要。
证据 / 可信度
931 条人工标注轨迹、6 个 benchmark、4 个 Agent、68 个 App，比较 6 种 Judge 方法与 5 个模型后端；论文含 bootstrap 和下游 RL 验证，但尚无独立复现。
与既有工作的差异
以往移动 Agent benchmark 常把 LLM Judge 当作可信组件；该工作把 Judge 本身变成一等评测对象，并验证指标能否预测排名和训练效用。
产品 / 评测意义
评测产品不应只提供一个自动分数，需要报告 Judge 的准确率、F1、平衡准确率、假阳性/假阴性和排名保真。
建议动作
先用现有移动轨迹构建人工金标子集，对照简单抽帧 Judge 与复杂 Judge，按错误成本选择 operating point。

今日论文

Benchmarking LLM Judges for Mobile Agent Evaluation

作者：Ziqiang Wan, Li Gu, Zhixiang Chi, Zhi Liu, Seyed Mehdi Ayyoubzadeh, Yuanhao Yu, Yang Wang
发布日期：2026-08-11 21:00 UTC
链接：arXiv · HTML · 代码：论文未提供可核验公开项目页

此前遇到的问题移动 Agent benchmark 越来越依赖 LLM Judge 判断任务完成，但 Judge 在真实轨迹上的可靠性、偏差和下游影响缺少系统验证。
研究做法收集 931 条人工标注轨迹，覆盖 6 个 benchmark、4 个 Agent、289 个任务和 68 个 App；比较 6 种 Judge 方法、5 个模型后端，并验证对 Agent 排名和 on-policy RL 的预测力。
关键结论均匀抽取截图的简单基线可与专用方法竞争并经常超过它们；竞争方法中底层模型是主要驱动。F1 与平衡准确率能预测排名保真；不同后端呈保守与宽松的相反错误模式。
与既有工作的差异不只比较 Agent，而是把评测器作为被测系统，并连接 intrinsic judge 指标、榜单排名与训练 reward 的真实效用。
可信度中高：人工多标注、跨 benchmark 与模型、2,000 次 task-cluster bootstrap、leave-one-out 和多 seed RL；但数据域仍局限 Android，Judge 调用存在供应商非确定性，尚无独立复现。
局限仅二分类任务完成；68 个 App 不能覆盖长期权限、不可逆副作用和跨设备状态；人工标签也可能含歧义；复杂 Judge 的成本/延迟比较仍需产品侧补测。
后续待验证加入部分完成、严重度加权、权限违规和不可逆错误；按不同业务错误成本校准阈值，并测试跨版本漂移。
展开英文简介与逐段中文翻译

English overview

MobileJudgeBench evaluates LLM judges on 931 human-annotated mobile-agent trajectories from six benchmarks, four agents, and 68 applications. It compares six judging approaches across five model backends and connects intrinsic judge quality to agent-ranking fidelity and reinforcement-learning utility.

The central result is deliberately practical: a simple judge using uniformly sampled screenshots is competitive with, and often better than, specialized pipelines. F1 and balanced accuracy predict ranking reliability, while backbone choice produces distinct conservative or permissive failure profiles. The work supports treating judge validation as a product requirement, although generalization beyond Android trajectories still needs independent testing.

对应中文翻译

MobileJudgeBench 在 931 条人工标注的移动 Agent 轨迹上评估 LLM Judge，数据来自 6 个 benchmark、4 个 Agent 和 68 个应用。研究比较了 5 个模型后端上的 6 种判断方法，并把 Judge 自身质量与 Agent 排名保真和强化学习效用连接起来。

核心结论很实用：使用均匀抽样截图的简单 Judge，可与专用复杂流水线竞争，并常常表现更好。F1 与平衡准确率能预测排名可靠性，而底层模型选择会产生明显的保守或宽松错误模式。该工作支持把 Judge 验证作为产品要求，但能否外推到 Android 之外仍需独立测试。
