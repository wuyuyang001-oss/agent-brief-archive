90 秒摘要

已证实：多 Agent 产品需要测量“如何协调”，不能只看最终成功率

新论文 / 方法增量
核心结论
将 Agent 与文件都作为节点，把消息、读写与成本变成带时间戳的边；1,902 次主实验显示任务结构决定网络形态，单纯在提示词里任命 coordinator 不会自然形成领导中心。
证据 / 可信度
主实验 1,902 次、封闭复现 244 次；团队规模 1–8，扩展臂至 16；代码、CSV、分析脚本和预注册记录已公开。可信度中等偏高，但只使用 Claude Code 2.1.x、claude-sonnet-4-6 和合成 Python 任务。
与既有工作的差异
已有评测多把拓扑当配置、把成功率与 token 当结果；这项工作把真实涌现出的协作网络、文件通道和接口失配变成评测对象。
产品 / 评测意义
多 Agent 评测应增加握手成本、持续通信度、文件复用率、接口所有权和重复运行方差；一个成功轨迹不足以证明架构稳定。
建议动作
在现有 Agent 流程埋点消息、读写、工具和时间；对同一配置至少重复 10 次，定位无人负责的跨 Agent 接口。

今日论文

When Agents Coordinate: Measuring Coordination in Multi-Agent AI Coding

作者：Giuseppe Destefanis、Tomaso Aste（University College London）
发布日期：2026-08-17 16:57 UTC
链接：arXiv · HTML · 代码、数据与预注册材料

此前遇到的问题多 Agent 编程通常只报告任务是否通过和总成本，无法解释团队为何成功、沟通是否浪费、哪一个跨 Agent 接口无人负责。
研究做法把 Agent 和文件都作为节点，把消息、文件写入与读取作为带时间戳、字节和 token 成本的边；在两类合成 Python 任务上交叉改变团队规模、团队结构与文件策略，收集 1,902 次主运行，并以 244 次封闭运行复验关键结论。
关键结论消息随人数增长的近二次成本主要来自早期“握手”；大团队转向广播后增长趋缓。共享文件在消息密集任务的 8 Agent 条件下降低约 42% 输出 token，但在已有文件流水线中增加约 10% 开销。只命名 coordinator 不形成结构中心，也没有可靠成功率收益。
与既有工作的差异既有工作通常预设链、星、树或角色，再对最终结果打分；本研究从运行轨迹中恢复实际涌现的网络，并把消息与持久文件放到同一个观测模型。
可信度中等偏高：样本量较大、每 cell 通常 10 次、提供精确区间与多重校正、关键结论做封闭复现，并公开完整 CSV、生成器、分析脚本和预注册材料。局限是单一模型/runtime、合成任务，且 93 个按预注册规则应补样的 cell 最终未补。
局限仅 Claude Code 2.1.x + claude-sonnet-4-6；shell 发起的文件操作不会形成边，约 0.6% 运行出现写入漏计；不同通道 token 归因不是完全同口径；主实验曾允许触达隐藏测试与参考答案。
后续待验证问题迁移到真实仓库、不同模型与运行时；验证握手是否能早期预测失败；比较“名义 coordinator”与真正有路由权、审批权、状态所有权的 orchestrator；把接口所有权纳入失败归因。
展开英文简介与逐段对应中文翻译

English overview

Most multi-agent coding evaluations retain the final patch, pass rate, and aggregate cost while discarding the coordination process. This work represents each run as a temporal heterogeneous network: agents and files are nodes, while messages, writes, and reads are timestamped, costed edges.

Across 1,902 controlled runs and 244 sealed replications, coordination depends on task structure. Shared files reduce repeated one-to-one communication when knowledge must be reassembled, but add overhead to an already file-mediated pipeline. A coordinator label alone creates neither a hub nor a reliable success gain, and repeated runs show that one configuration should be treated as a distribution rather than a single trace.

对应中文翻译

多数多 Agent 编程评测只保留最终补丁、通过率和总成本，却丢失协作过程。本研究把每次运行表示为异构时间网络：Agent 和文件是节点，消息、写入和读取是带时间戳与成本的边。

在 1,902 次受控运行和 244 次封闭复现中，协调方式取决于任务结构。需要重组知识时，共享文件能减少重复的一对一沟通；已经依赖文件传递的流水线中，它反而增加开销。只有 coordinator 标签既不会形成中心，也不会稳定提高成功率；重复运行还说明同一配置应被视作一个分布，而不是一条轨迹。
