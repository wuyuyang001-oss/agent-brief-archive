From Agent Behaviour to Agent-Friendly Documentation: An Empirical Study of How Coding Agents Discover, Read, and Write Technical Documentation

作者：Zhijun Gao、Jing Chen
发布日期：2026-08-20
链接：arXiv · HTML · TeX source / replication description
代码 / 项目页：论文声明发布 replication package，但 arXiv HTML 与源包未暴露独立稳定 URL；不虚构链接。

此前遇到的问题“Agent-friendly documentation”多基于人类文档经验或直觉，没有回答 Agent 实际读什么、何时读、读完做什么。
研究做法结合 SWE-chat 的 557 次真实会话（94,813 个事件、3,033 次文档交互）与 AIDev 的 33,097 个 Agent PR（690,260 条文件级变化），做路径分类、事件序列、cluster bootstrap 和阶段调整模型。
关键结论Agent-facing 指令与工作笔记占 60.5%；API reference 仅 1.3%；70.2% 文档交互为自发；没有观察到显式文档校验序列；多 commit PR 中代码先于文档的概率约为反向的 4.7 倍。
与既有工作的差异不先规定好文档品质再测效果，而是从真实 Agent 轨迹反推文档设计；还区分“描述 Agent 做了什么”和“证明这样做有效”。
可信度中等：两个公开数据集、事件与 PR 两种单位互补，区间考虑聚类，作者主动拒绝小样本强结论；提供提取管线、编码方案和事件级材料描述。
局限观察性数据不能证明因果；路径方法漏掉 docstring 和注释；工作笔记的二级分类未经人工验证；SWE-chat 不能看 merge 结果，AIDev 没有工具轨迹；大仓库聚类明显，外推到私有企业代码有限。
后续进展 / 待验证人工双标 200–300 个事件验证分类；对指令文件做任务级消融；把可执行断言写入文档并测测试行为；追踪文档变更是否改善实际修复，而非只增加阅读。
展开英文简介与逐段对应中文翻译

English overview

This study examines how coding agents interact with documentation in real development traces. Across 557 SWE-chat sessions and 33,097 agentic pull requests, agent-facing instruction files and working notes dominate documentation activity, while conventional API references represent only a small fraction.

The traces do not support a simple read-then-code-then-validate journey. Documentation reads are usually followed by more reading or reasoning, no explicit documentation-based validation sequence is observed, and code tends to precede documentation in multi-commit pull requests. The authors therefore describe a two-lobed cycle and call for documentation properties to be tested behaviourally rather than assumed.

逐段中文翻译

这项研究考察 coding Agent 在真实开发轨迹中如何与文档交互。在 557 次 SWE-chat 会话和 33,097 个 Agent PR 中，面向 Agent 的指令文件与工作笔记主导文档活动，传统 API reference 只占很小一部分。

这些轨迹不支持简单的“阅读—编码—验证”线性过程。读文档之后通常是继续阅读或推理，没有观察到显式的文档校验序列；在多 commit PR 中，代码也往往先于文档。作者据此提出双叶循环，并主张通过行为实验验证文档属性，而不是默认它们有效。
